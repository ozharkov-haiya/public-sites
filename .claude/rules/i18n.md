# i18n rules

- **Dictionaries are plain typed objects.** `en.ts` defines the shape (`Dictionary`). Every other
  locale is `const xx: Dictionary = {...}`, so a missing or extra key fails `pnpm check`. Never
  loosen this with `Partial`, `as`, or `any`.
- **Group keys by where they appear:** `meta`, `a11y`, `nav`, then one group per section
  (`hero`, `features`, ...) and per page (`notFound`, `about`, ...). Section components read
  only their own group.
- **Lists are arrays in the dictionary** (see `features.items`), so each locale can have
  different wording while keeping the same number of items.
- **Interpolation:** `{name}` placeholders + `format(t.x.y, { name })`. Don't build sentences from
  parts: word order differs between languages.
- **Rich text** (a link inside a sentence): split into `before` / `linkText` / `after` keys.
  Don't use `set:html` on dictionary strings.
- **Getting the locale:** pages get it from `Astro.props.locale` (via `getLocaleStaticPaths`)
  and pass it down as a `locale` prop. Components don't read `Astro.currentLocale`, so the
  dependency stays visible.
- **URLs:** `localizePath(locale, '/about')` for links, `localizeUrl` for absolute URLs
  (canonical, OG). Hash links: `${localizePath(locale)}#section`.
- **Formatting numbers/dates/currency:** `new Intl.NumberFormat(locale, ...)` /
  `Intl.DateTimeFormat`. Never format them by hand.
- **Language switcher** links to the same route in other locales, with `hreflang` and `lang`
  attributes. It never auto-redirects by browser language.
- New locale? Follow the `add-locale` skill.
